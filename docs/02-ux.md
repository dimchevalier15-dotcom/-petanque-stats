# Pétanque Analytics

# 02 - Expérience utilisateur (UX)

**Version :** 0.1

**Statut :** Validé

---

# Philosophie

L'utilisateur ne doit jamais avoir l'impression de remplir un formulaire.

Chaque écran doit permettre d'effectuer une action rapidement.

Le nombre d'écrans est volontairement limité.

Le nombre de clics doit rester minimal.

---

# Parcours utilisateur

Connexion

↓

Accueil

↓

Création d'un match

↓

Saisie des mènes

↓

Contexte de fin de partie

↓

Envoi du Match

---

# Les écrans V1

La V1 comporte uniquement cinq écrans principaux.

- Connexion
- Accueil
- Création d'un Match
- Match
- Fin de Match

Tout le reste doit être intégré dans ces écrans.

---

# 1. Connexion

Objectif :

Permettre l'accès à l'application.

Une fois connecté :

- l'utilisateur reste connecté ;
- aucune reconnexion n'est demandée tant que le token reste valide.

---

# 2. Accueil

L'écran d'accueil est volontairement minimal.

Actions disponibles :

- Nouvelle partie
- Reprendre une partie (si un MatchDraft existe)

Les statistiques, l'historique et le profil ne font pas partie de la V1.

---

# 3. Création d'un Match

Toutes les informations nécessaires sont regroupées sur un seul écran.

Aucun assistant ("wizard") ne doit être utilisé.

## Informations générales

- Format
    - Tête-à-tête
    - Doublette
    - Triplette

- Mode de notation
    - Standard
    - Simple

---

## Les équipes

Deux équipes sont créées.

Chaque joueur est ajouté par autocomplétion.

Recherche instantanée dans les Players existants.

Si aucun Player ne correspond :

La liste de suggestions propose directement d'ajouter le nom saisi comme participant du match.

Le participant est alors provisoire.

Aucun formulaire, aucun changement d'écran.

---

## Participant provisoire

Un participant provisoire n'existe que dans la sauvegarde locale du match.

Il porte uniquement un libellé.

Il se comporte exactement comme un joueur réel pendant toute la partie.

Il est rattaché à un Player existant, ou créé en base, à la fin du match.

Voir US-021.

---

## Création d'un Player

La création d'un Player ne doit pas interrompre le flux.

Elle s'effectue à la fin du match, depuis l'écran de résolution des participants.

Objectif :

Créer un Player en quelques secondes.

### Champs obligatoires

- Prénom
- Nom

### Champs facultatifs

- Surnom
- Pays
- Club

Aucun autre champ n'est obligatoire.

---

## Pour chaque joueur

Deux informations sont définies.

### Rôle initial

- Pointeur
- Milieu
- Tireur

Le rôle sert uniquement à pré-sélectionner le type d'action pendant le Match.

---

### Analyse

Chaque joueur possède un interrupteur.

Valeurs :

- Oui
- Non

Par défaut :

Tous les joueurs sont analysés.

Si l'analyse est désactivée :

Le joueur participe normalement au Match mais aucune Action ne sera enregistrée.

---

# 4. Match

C'est l'écran principal de l'application.

La quasi-totalité du temps passé dans l'application se déroule ici.

Aucune navigation ne doit être nécessaire pendant une mène.

---

## Informations affichées

- numéro de la mène
- score
- équipe qui commence
- distance estimée (facultative)

---

## Distance estimée

Un champ de distance est affiché en permanence.

Caractéristiques :

- facultatif ;
- modifiable à tout moment ;
- jamais bloquant.

La valeur est copiée dans chaque nouvelle Action.

---

## Les joueurs

Seuls les joueurs analysés apparaissent.

Chaque joueur possède :

- son nom ;
- le type d'action sélectionné ;
- les boutons de notation.

---

## Type d'action

Le type est automatiquement proposé selon le rôle.

Valeurs :

- Point
- Tir

L'utilisateur peut toujours le modifier.

---

## Notation

### Mode Standard

Boutons :

+2

+1

0

-1

-2

---

### Mode Simple

Boutons :

Réussie

Ratée

Conversion automatique :

Réussie → +1

Ratée → -1

---

## Création d'une Action

Une Action est créée immédiatement après le choix d'une note.

Aucune validation supplémentaire.

---

## Validation d'une mène

Une fois toutes les Actions saisies :

L'utilisateur indique :

- quelle équipe marque ;
- combien de points.

La mène est alors validée.

Le score n'est jamais calculé automatiquement.

---

## Correction

À tout moment avant la fin du Match :

Il est possible de :

- modifier une Action ;
- supprimer une Action ;
- revenir sur une mène précédente.

Le Match reste entièrement modifiable.

---

# 5. Fin de Match

Une fois le Match terminé :

Si le Match contient des participants provisoires, un écran de résolution est affiché.

Cet écran est le seul obligatoire : un Match ne peut pas être enregistré tant qu'un participant
n'est pas rattaché à un Player.

Puis un écran de contexte facultatif est proposé.

Il ne doit jamais empêcher la sauvegarde du Match.

---

## Résolution des participants

Pour chaque participant provisoire, deux choix :

- rattacher un Player existant ;
- créer un nouveau Player.

Le libellé saisi pendant la partie est proposé comme valeur initiale.

---

## Informations de contexte

Type de partie :

- Entraînement
- Amicale
- Compétition

Si Compétition :

- Nom
- Stade

Le terrain est sélectionné dans une liste.

Un commentaire libre peut être ajouté.

Tous les champs sont facultatifs.

---

# Sauvegarde

Pendant toute la partie :

Le Match est stocké localement.

Des sauvegardes régulières permettent de reprendre une partie interrompue.

Aucune communication réseau n'a lieu pendant le Match.

---

# Envoi

À la fin de la partie, et seulement à ce moment, le Front envoie le Match au backend.

L'envoi se déroule en trois étapes : les Players manquants, le Match, puis son contenu.

La progression est mémorisée localement.

Un échec réseau ne perd aucune donnée et ne crée aucun doublon.

Voir ADR-001.

---

# Principes UX

Toujours privilégier :

- moins de clics ;
- moins d'écrans ;
- moins de saisie.

Une donnée facultative ne doit jamais ralentir un utilisateur qui ne souhaite pas la renseigner.

---

# Objectif

Un utilisateur découvrant l'application doit pouvoir :

- créer un Match ;
- enregistrer une partie complète ;
- terminer la saisie ;

sans avoir besoin d'explication.
